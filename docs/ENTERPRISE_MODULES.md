# IntelliScholar 企业级/工业级上线功能模块清单

本文档基于当前代码库（LangGraph + FastAPI + Streamlit）现状，列出要**企业级/工业级上线**时建议新增或强化的**前后端功能模块**，便于按优先级落地。

---

## 一、当前已有能力（简要）

| 能力 | 现状 |
|------|------|
| 推荐流程 | LangGraph 多智能体 + 后端 workflow，支持 RAG/在线检索/ItemCF 等 |
| API | FastAPI：`/recommendations/`、`/daily/{user_id}`、用户画像与反馈 |
| 前端 | LangGraph Web（会话式）+ Streamlit MVP（调用后端 API） |
| 数据 | PostgreSQL（元数据+用户画像）、ChromaDB/可选 Milvus、Redis 配置存在 |
| 认证 | 无 API 鉴权；Web 仅 in-memory session |

---

## 二、后端需新增/强化的功能模块

### 1. 认证与授权（必须）

- **API 鉴权**
  - **JWT**：登录后签发 access/refresh token，access 短期、refresh 长期；接口校验 Bearer token。
  - **API Key**：为机器/第三方分配 API Key，用于服务间调用或开放 API；需存储、轮换、作废。
- **登录方式**
  - 用户名/邮箱 + 密码（bcrypt/argon2 哈希）。
  - 可选：OAuth2/SSO（企业微信、钉钉、Google 等）。
- **权限模型**
  - **RBAC**：角色（如 admin、researcher、api_client）与权限（如读推荐、写反馈、管理用户）解耦，接口按权限校验。
- **会话与安全**
  - 会话存储：Redis（替代 in-memory），支持分布式与过期。
  - 防暴力破解：登录失败次数限制、验证码/人机校验（关键接口）。
  - 敏感操作：二次验证或操作确认（可选）。

**落地建议**：新增 `backend/api/auth.py`（登录/登出/刷新）、`backend/services/auth.py`（JWT/API Key 校验）、中间件或依赖项做统一鉴权；用户表与角色/权限表设计在 PostgreSQL。

---

### 2. 限流、熔断与稳定性（必须）

- **限流（Rate Limiting）**
  - 按用户/API Key/IP 限制 QPS 或每日调用量，防止滥用与成本失控。
  - 推荐：Redis 滑动窗口或令牌桶；可区分接口（如推荐接口更严格）。
- **熔断与降级**
  - 对 LLM、向量库、外部 API（如 Semantic Scholar）做熔断：失败率/延迟超阈值时短路，返回缓存或简化结果。
  - 超时控制：所有外部调用与 agent 步骤设 timeout，避免长时间挂起。
- **幂等与重试**
  - 写操作（如反馈、用户更新）支持幂等键，避免重复提交。
  - 可配置重试（指数退避）仅针对可重试错误。

**落地建议**：中间件实现限流（或使用 slowapi 等）；在调用 LLM/向量/外部 API 的封装层做熔断与超时。

---

### 3. 可观测性（必须）

- **结构化日志**
  - 请求 ID 贯穿全链路，日志带 level、timestamp、user_id、request_id、error_code。
  - 敏感信息脱敏（如 token、密码不落盘）。
- **指标（Metrics）**
  - 暴露 Prometheus 格式 `/metrics`：请求量、延迟分位、错误率、按接口/用户分布。
  - 业务指标：推荐请求数、召回/排序阶段耗时、LLM 调用次数与 token 用量。
- **链路追踪（Tracing）**
  - OpenTelemetry 集成：从 API 到 LangGraph、向量库、LLM 的 trace，便于排查延迟与异常。
- **健康检查**
  - `/health` 细化：依赖项状态（PostgreSQL、Redis、ChromaDB/Milvus、可选 LLM 连通性），返回 503 当依赖不可用。

**落地建议**：`backend/middleware/` 中 request_id、logging；`/metrics` 用 prometheus_client；tracing 在 FastAPI 与 LangGraph 入口埋点。

---

### 4. 配置与密钥管理（必须）

- **环境区分**
  - 明确 dev / staging / prod 配置（含 CORS、限流阈值、日志级别、特性开关）。
- **密钥**
  - 生产环境密钥不进代码库，使用环境变量或企业密钥管理（如 Vault、云 KMS）。
- **特性开关（Feature Flags）**
  - 新策略/新模型通过开关控制灰度与回滚，减少发布风险。

**落地建议**：在现有 `backend/config.py` 上按环境扩展；敏感项仅从环境或密钥服务读取。

---

### 5. 数据与存储（必须）

- **数据库初始化与迁移**
  - 启动时检查/执行迁移（如 Alembic），保证表结构与版本一致。
  - 在 `startup_event` 中初始化连接池、健康检查依赖。
- **连接池与超时**
  - PostgreSQL、Redis 使用连接池；设置连接/查询超时，避免拖垮服务。
- **备份与恢复**
  - 定期备份 PostgreSQL、向量库与关键配置；有恢复与 RTO 目标。

---

### 6. 管理后台 API（强烈建议）

- **用户管理**
  - 列表、搜索、禁用/启用、重置密码、角色分配。
- **内容/数据管理**
  - 论文源管理（导入、更新、下线）、向量库与元数据同步状态。
- **系统配置**
  - 限流阈值、特性开关、推荐策略默认值等可配置化。
- **运营看板数据**
  - 调用量、错误率、热门查询等聚合接口，供管理前端或报表使用。

**落地建议**：`backend/api/admin/` 下分路由（users、papers、config、stats）；所有接口需 admin 权限校验。

---

### 7. 审计与合规（按需）

- **审计日志**
  - 关键操作写审计表或日志：登录、权限变更、敏感数据访问、配置修改；不可篡改（只追加）。
- **数据保留与脱敏**
  - 日志与行为数据保留策略；对外输出或导出时用户信息脱敏。
- **合规**
  - 若涉及个人数据，需符合公司隐私政策与当地法规（如告知、同意、删除权）。

---

### 8. 部署与运维（必须）

- **容器化**
  - 提供 `Dockerfile` 与 `docker-compose`（含 app、PostgreSQL、Redis、可选 Milvus）；生产可改为 K8s 编排。
- **进程与高可用**
  - 使用 gunicorn/uvicorn worker、多实例 + 负载均衡；无状态设计，会话在 Redis。
- **CI/CD**
  - 自动化测试、构建镜像、部署到 staging/prod；数据库迁移在流水线中可控执行。
- **文档**
  - 维护 `.env.example` 与部署文档（端口、依赖、最小资源配置）。

---

## 三、前端需新增/强化的功能模块

### 1. 统一产品前端（强烈建议）

- **技术选型**
  - 企业级建议用 **React/Vue + TypeScript** 的 SPA，替代或与现有 Streamlit 并存；Streamlit 可保留为内部/演示用。
- **与后端对齐**
  - 所有请求走同一套后端 API（建议以当前 FastAPI 为唯一生产 API），统一鉴权（Cookie + JWT 或 Bearer）。
- **LangGraph 对话**
  - 若保留会话式推荐，可将 LangGraph Web 的对话能力封装为 API，由统一前端调用并渲染。

---

### 2. 登录/注册/账户（必须）

- **登录页**
  - 账号密码登录；可选“记住我”、SSO 入口。
- **注册**
  - 邮箱/手机验证、密码强度、协议勾选；可选邀请码/审批流。
- **找回密码**
  - 邮件/短信链接或验证码重置密码。
- **登出**
  - 清除本地 token 并调用后端登出（使 refresh token 失效）。

---

### 3. 用户中心与设置（强烈建议）

- **个人资料**
  - 展示与编辑：昵称、头像、领域、兴趣标签（与当前用户画像一致）。
- **安全设置**
  - 修改密码、绑定/解绑邮箱或手机、API Key 自助申请与查看（若开放）。
- **偏好设置**
  - 默认推荐数量、召回策略偏好、通知偏好等，与后端 `user_profile` 或配置 API 同步。

---

### 4. 推荐与内容消费（强化现有）

- **推荐结果页**
  - 列表/卡片展示；筛选、排序、分页；请求 ID 便于反馈与排查。
- **反馈闭环**
  - 点赞/点踩、收藏、已读、不感兴趣；与现有 `POST /users/{user_id}/feedback` 对接，并刷新画像。
- **详情与导出**
  - 论文详情（摘要、引用、链接）；导出为 BibTeX/CSV/阅读列表。
- **每日推荐**
  - 独立入口调用 `GET /recommendations/daily/{user_id}`，支持“明日再推”等交互。

---

### 5. 管理后台前端（强烈建议）

- **仪表盘**
  - 调用量、错误率、延迟趋势；依赖健康状态。
- **用户管理**
  - 用户列表、搜索、禁用/启用、角色、操作审计。
- **内容/论文管理**
  - 数据源、导入任务、向量库状态。
- **系统配置**
  - 限流、特性开关、推荐策略默认值；需权限控制与操作日志。

---

### 6. 监控与运维视图（按需）

- **运维大屏**
  - 服务状态、依赖健康、告警摘要；只读，权限受限。
- **日志查询**
  - 按 request_id、user_id、时间范围查询日志（对接后端或日志平台）。

---

## 四、模块优先级建议

| 优先级 | 模块 | 说明 |
|--------|------|------|
| P0 | 认证与授权、限流、健康检查与启动初始化 | 安全与可用性基础 |
| P0 | 结构化日志、Metrics、基础 Tracing | 问题定位与容量评估 |
| P0 | 配置/密钥、Docker + 部署文档、DB 迁移 | 可部署、可运维 |
| P1 | 统一前端 + 登录/注册、用户中心 | 完整用户体验 |
| P1 | 管理后台 API + 前端、推荐页反馈与导出 | 运营与迭代 |
| P2 | 熔断/降级、审计日志、特性开关 | 稳定性与合规 |
| P2 | 监控大屏、日志查询 | 运维效率 |

---

## 五、与现有代码的衔接点

- **认证**：在 `backend/main.py` 或路由层加入鉴权中间件/依赖，对 `backend/api/*` 统一校验；LangGraph Web 若对外提供，也需走同一鉴权或网关。
- **限流**：在 FastAPI 层加中间件，按 `user_id` 或 `api_key` 限流。
- **可观测性**：在 `main.py` 注册 middleware；在 `recommendation_workflow` 与 LangGraph 关键节点打点与传递 request_id。
- **管理 API**：在 `backend/api/__init__.py` 中 `include_router(admin_router, prefix="/admin", ...)`，并限制为 admin 角色。
- **前端**：新 SPA 使用 `VITE_APP_API_BASE_URL` 等指向当前 FastAPI 的 `/api/v1`，复用现有 recommendations、users、auth（新增）接口。

按上述模块分阶段实施，可逐步达到企业级/工业级上线要求；若你希望先实现某一块（例如先做 JWT + 限流），可以指定模块，我可以按当前项目结构给出具体改动方案与示例代码。
